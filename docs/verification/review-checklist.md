# Review checklist

This checklist assesses the documentation snapshot; runtime acceptance remains in the separate acceptance plan.

- Problem, fictional consumer, monthly source and exclusions are explicit.
- Source assertions have URLs, observation dates, methods and uncertainty.
- Requirements map to design owners and tests or documentary checks.
- Source/revision/row/attempt/derivation/release/selection identities are distinct.
- Adapter rules preserve absent/null/zero and exact raw evidence.
- Publication, recovery, rollback, rejection and cleanup have auditable outcomes.
- Rules distinguish exceptions from failed evaluation; numerical oracles are independent of future implementation.
- Reader caches cannot bypass eligibility; resources are budgeted for writer and consumer together.
- ADRs record tradeoffs and concrete revisit triggers.
- All local links remain inside this package; no private profile paths or material are included.
- Manifest hashes match actual files. No repository, source code, executable configuration or generated data is present.
- Runtime claims remain pending: compatibility, full-month/year scale, recovery and UI behavior.

Do not interpret checked file presence as behavioral verification. The transfer snapshot is ready only when its review result and any remaining documentary gaps are recorded. Publication remains a separate user decision.
