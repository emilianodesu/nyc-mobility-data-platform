# HVFHV — Data and quality contracts v1

Date: 2026-11-09. Design only. Parent: [low-level design](LOW-LEVEL-DESIGN-v1.md). Research observations: [feasibility](../runs/2026-11-08-tlc-feasibility/FINDINGS.md) and [semantic inspection](../runs/2026-11-09-hvfhv-architecture/ARCHITECTURE-REVIEW.md). Samples do not establish population-level defect rates.

## 1. Source contract and adaptation

Accept only supported named contracts, not arbitrary union-by-name. Initial variants: 24-column pre-2025 and 25-column 2025-onward schema with `cbd_congestion_fee`. Validate against source month and actual schema; unexpected combinations stop for review. Unknown added fields preserve original bytes but block normalization until an adapter revision documents their treatment. Column order is not semantic; changed physical/logical types require an explicit lossless mapping. `string/large_string` map to VARCHAR; timezone-bearing timestamps do not silently map to naive timestamps.

| Source fields | Normalized type | Null / value policy |
| --- | --- | --- |
| `hvfhs_license_num`, `dispatching_base_num`, `originating_base_num` | VARCHAR | Preserve null and exact code; no trim/case correction without explicit transformation |
| `request_datetime`, `on_scene_datetime`, `pickup_datetime`, `dropoff_datetime` | TIMESTAMP at microsecond precision, no timezone | Preserve source values; no UTC assumption |
| `PULocationID`, `DOLocationID` | INTEGER, renamed `pu_location_id`, `do_location_id` | Nullable; unmatched/sentinel values remain visible |
| `trip_time` | BIGINT | Source duration retained independently of timestamp arithmetic |
| `trip_miles` | DOUBLE | Preserve negatives, zero, NaN/Inf and classify; not all imply same issue |
| `base_passenger_fare`, `tolls`, `bcf`, `sales_tax`, `congestion_surcharge`, `airport_fee`, `tips`, `driver_pay`, `cbd_congestion_fee` | DOUBLE | Preserve reported floating values; no claimed exact financial ledger or inferred payment total |
| `shared_request_flag`, `shared_match_flag`, `access_a_ride_flag`, `wav_request_flag`, `wav_match_flag` | VARCHAR | Preserve raw values; domain discoveries reported, no Boolean coercion of unknowns |

Missing `cbd_congestion_fee` in a supported older schema becomes NULL with `cbd_fee_field_present=false`, not zero. Original schema manifest distinguishes absent field from present-but-null. Data-value nulls are generally semantic findings; missing required columns are structural failures. Exact Arrow schema, metadata row counts and full decoded row counts are separately recorded.

Zone source: explicit CSV header mapping for `LocationID`, `Borough`, `Zone`, `service_zone`; unique non-null integer location IDs mandatory. Blank names remain profiled. Observed special IDs 264/265 are Unknown/Outside NYC, and ID 1 is Newark Airport; retain these categories instead of dropping nonstandard boroughs. No history or valid-from dates are inferred from one current lookup. Digest-bound zone version applies to the release.

## 2. Analytical relations

All tables live in one release database. Source amounts and timestamps are retained in `trip_observation`; derived eligibility is distinct from source values.

| Relation / grain | Required columns and constraints |
| --- | --- |
| `release_metadata`, exactly one row | Release/derivation IDs, model/rule/metric/code/lock versions, zone revision, configured first/last source month, build time; matches manifest |
| `source_contribution`, one per monthly object | Logical source, revision, SHA, source month, source schema version, decoded row count, inserted row count; counts must agree |
| `trip_observation`, one per physical original row | All normalized fields above, revision ID, source month, source row number; logical uniqueness `(revision_id,source_row_number)` checked; no invented business PK |
| `zone_reference`, one per LocationID | Lookup labels and reference revision; exactly one release-level reference version |
| `trip_qualified`, view over observations | Derived recorded interval, interval eligibility/reason, pickup date/month/hour, off-source-month flag, zone status, temporal flags and nonfinite flags |
| `quality_result`, one per pre-seal data rule/cohort | Rule ID/version, cohort key, severity, status, method, evaluated count, exception count, denominator, nullable rate, details/reason, source provenance; S08 belongs to control attestations outside this DB |
| `column_profile`, one per source/cohort/column/statistic | Statistic name, typed value, method `full_scan/footer/sample/approximate`, population count, null/nonfinite counts; sample metadata only if explicitly used |
| `interval_daily`, source month × recorded pickup date × pickup zone × license | Total, eligible, missing, negative counts, median seconds, p95 seconds; null groups retained |
| `interval_monthly`, source month × recorded pickup month × pickup zone × license | Same counts and exact independently recomputed quantiles; source/event month both explicit |
| `coverage`, one per configured source month | Expected/available/included flags, revision and row count; absent is NULL count, not zero |

Repeated publication metadata does not need a per-row UUID column in hundreds of millions of observations. Relations are scoped to one release; source revision provides row lineage. Large uniqueness checks and aggregate sorts must obey the measured resource gate. Additional indices require measured query benefit.

## 3. Recorded request-to-pickup definition

Metric ID `recorded_request_to_pickup_seconds.v1` = `(pickup_datetime - request_datetime)` in microseconds divided by 1,000,000, preserving fractional seconds. Do not use calendar-boundary second counting if it truncates precision. The source timestamps are naive; result is arithmetic on recorded wall-clock values, not proven elapsed physical time. DST and scheduled-request meaning remain limitations on interpretation. No inferred UTC conversion.

Mutually exclusive interval classes, in priority order:

1. `missing_timestamp`: request or pickup is NULL.
2. `negative_recorded_interval`: both present, result < 0.
3. `eligible_nonnegative_recorded_interval`: both present, result >= 0.

Thus `total = missing + negative + eligible`. Zero is eligible. Long positive intervals remain eligible and visible in distributions; there is no selected arbitrary maximum. Timezone uncertainty applies to all rows and is not presented as a row-level confirmed fault. Other metric definitions can choose stricter eligibility only through versioned amendments.

Median and p95 use exact continuous quantiles (linear interpolation, DuckDB `quantile_cont` semantics) over the eligible population. Empty population → NULL quantile and zero eligible count. Single observation → that value. Cross-day/month summaries read the underlying eligible values, never average or percentile the subgroup quantiles. Counts include NULL grouping categories. Rates use an explicit denominator, with NULL when denominator is zero.

`on_scene_datetime` is profiled by source month/license and compared with request/pickup timestamps. It is not used as universal arrival time. `trip_time` vs recorded dropoff-minus-pickup produces signed difference profiles; exact disagreement is a finding, not a rejection or claim of incorrect source data.

## 4. Required rule inventory

Status enum: `PASS/FAIL/ERROR/NOT_APPLICABLE`; semantic checks use FAIL to identify exceptions without blocking release. Severity controls publication. A warning with no baseline is NOT_APPLICABLE with reason, not PASS. Every expected rule/cohort must exist exactly once. Denominator/evaluation scope is explicit; aggregate warning count is not a universal data-quality score.

Two inventories avoid hash circularity: pre-seal S01–S07 and Q01–Q09 persist in the DB/report; post-seal S08 persists only in registry `release_verifications`, bound to final artifact hashes. S07 verifies all other pre-seal outcomes, then writes its own outcome; publish validates the complete expected inventory including S07 independently. Final validation-report serialization checks this inventory before hashing. No file contains a result that depends on that same file's final digest.

Publication truth table: every BLOCK rule must be PASS; WARN rules may be PASS or FAIL (observed exceptions), or NOT_APPLICABLE only for a reason explicitly permitted by that rule. ERROR, missing result, duplicate result or unrecognized status blocks publication at every severity. A generic NOT_APPLICABLE must not hide an unsupported computation. Empty valid populations retain counts and NULL statistics with an explicit empty-population reason. Q09 reports differences without a significance threshold: successful computation is PASS, not a claim of no drift; Q07 flags newly observed codes as FAIL/WARN. Thus a real source with negative recorded intervals can be published with visible findings, while a failed interval computation cannot.

| ID | Scope and precise predicate / result | Severity / method |
| --- | --- | --- |
| S01 | Complete file, matching digest/size, readable footer and full decoded ingestion | BLOCK / bytes + full decode |
| S02 | Named schema adapter and required columns/types match | BLOCK / schema |
| S03 | Selected zone IDs unique and non-null | BLOCK / full scan |
| S04 | Every configured month has exactly one selected contribution; exact selected revision set equals plan | BLOCK / manifest + model |
| S05 | Each contribution: decoded = inserted = expected footer rows; locators unique and contiguous 0..n-1 | BLOCK / full scan |
| S06 | Every published model, rule result and reference belongs to this derivation; no stale contribution | BLOCK / reconciliation |
| S07 | Required rule inventory completed without ERROR/missing rows; metric count identities hold | BLOCK / inventory + full scan |
| S08 | Closed DB/validation hashes match manifest; release metadata and supported schema match | BLOCK / bytes + read-only inspection |
| Q01 | Null count/rate for every source column, per source and license | WARN / full scan |
| Q02 | Recorded interval missing/negative/zero/positive counts and exact quantiles; mutually exclusive arithmetic as above | WARN / full scan |
| Q03 | Pickup/dropoff reversed, on-scene temporal comparisons, signed trip-time discrepancy distribution | WARN / full scan; comparisons only when operands present |
| Q04 | Pickup month differs from source month; missing pickup separate | WARN / full scan |
| Q05 | Pickup/dropoff location NULL, matched ordinary, matched sentinel or unmatched; exclusive categories | WARN / full scan |
| Q06 | Numeric null/NaN/Inf/negative/zero/positive counts; finite-only range/quantiles with explicit exclusions | WARN / full scan |
| Q07 | License/base/flag domains and cardinalities; new observed values against the adjacent prior source month inside the same frozen plan | WARN / full scan |
| Q08 | Exact equality groups across all normalized source fields within each source revision; group count and excess rows | WARN / full scan; no deletion |
| Q09 | Null-rate, row-count and quantile changes by month/license against adjacent source month in the frozen plan; report raw difference and comparable populations | WARN / full scan; no uncalibrated anomaly gate |

Q08 uses explicit all-source-column grouping with documented SQL null/NaN equality; provenance is excluded from comparison. A hash may accelerate grouping only if equality is confirmed on original values. Across-month equal rows are outside Q08's detection claim. Do not call equality a proven duplicate trip.

Q07/Q09 never depend implicitly on execution history. No prior month in the plan means NOT_APPLICABLE with reason. Missing license cohorts are labeled absent, not silently coerced to zero-rate cohorts. Comparisons identify descriptive changes, not causal anomalies.

Source publication delay and time since last successful check are operational observations, not source-data exceptions. A failed source check must not update last-success time. A missing next month produces unavailable/stale information, not invented zero activity. Initial configured complete-window gaps block first publication; later failed acquisition leaves the prior release available and explicitly stale relative to the pending plan.

## 5. Consumer evidence and interpretation

Reliability view: selected release, configured coverage, file revisions, full-scan vs metadata provenance, check results, exception cohorts, prior publication, pending/failed run and separate last successful source check. It must distinguish latest observed available month from current included month and first observed availability from unknowable exact upstream publication time.

Interval view: exact filter population, total/eligible/missing/negative counts, eligible fraction, recorded median/p95, pickup zone/license/date, source-month coverage and limitations. No claim of cancellations, rejected demand, all requests, dispatch SLA, customer satisfaction or causal effect. The source describes published trip observations, not a complete request event log.

## 6. Evidence sources

- [TLC trip records](https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page): monthly source and publication changes.
- [HVFHV dictionary](https://www.nyc.gov/assets/tlc/downloads/pdf/data_dictionary_trip_records_hvfhs.pdf): source field definitions; semantic uncertainties in the linked research remain unresolved.
- [Taxi zones](https://d37ci6vzurychx.cloudfront.net/misc/taxi_zone_lookup.csv): reference vocabulary, not slowly changing history.
- [DuckDB aggregates](https://duckdb.org/docs/2.0/sql/functions/aggregates): continuous quantile and empty-population behavior; the selected population remains a project policy.

Policies such as warning eligibility, exact quantile convention and no automatic deduplication are project decisions informed by these sources, not guarantees supplied by TLC.
